# 検証可能予想の台帳 (公開ミラー)

このリポジトリは、封印済み成果物と、そこから決定的に再生成されたページの**ミラー**です。
ここで新しく作られる数字はひとつもありません。

- `index.md` — 台帳の入口 (日次台帳・較正表・スコアボード・主張しないこと・撤退条件)
- `daily/<日付>/` — 封印そのもの (スケジュール宣言・レース別ペイロード・日次マニフェスト・RFC3161 応答)
- `data/<日付>.json` — 機械可読データ
- `evidence/` — 公式構成を決めた前向き測定 (成果物 JSON とレース明細パネル)
- `verify_chain.py` — 第三者検証スクリプト (標準ライブラリのみ)

## 検証

```bash
python verify_chain.py
```

ハッシュ連鎖・宣言レース数・欠落日を、封印済みバイト列から再計算して照合します。
RFC3161 タイムスタンプの暗号検証は `openssl ts -verify` で別途行えます (手順は `verify.md`)。

**全体検証は過去の異常により不合格です。** 2026-08-30、09-04、09-14には、
封印済みスケジュールの宣言外にレース封印があります。元の封印は変更せず、
`incidents/schedule_overflow_2026.json` に現物のハッシュと件数を記録しています。
日次の独立検証が通って公開された日も、全体連鎖が合格したという意味ではありません。

封印時点の市場ベクトルは含まれていません (オッズ板の再配布可否が法務確認中のため)。
その RFC3161 応答 (`*.market.json.tsr`) も同様に含めていません — 対象ファイルが無ければ
タイムスタンプは検証できないので、置いても意味がないためです。
**クローズ済みの日**はマニフェストが市場記録のハッシュを持つので、封印との結びつきは
中身なしで検証できます。**未クローズの日**にはマニフェストが無いため比較先が存在せず、
`verify_chain.py` はその旨を明示して先へ進みます (失敗ではありません)。
